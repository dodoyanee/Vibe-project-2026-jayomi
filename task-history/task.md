- 사용자가 Tailwind, GSAP ScrollTrigger, Lenis의 CDN 사용과 두 번째 섹션/헤더 스크롤 모션을 명시적으로 요청했다. `index.html`에 고정 버전 Tailwind Browser 4.1.18, GSAP/ScrollTrigger 3.13.0, Lenis 1.3.27 및 Lenis CSS를 연결했다. 모든 새 외부 파일은 실제 응답으로 SHA-384 해시를 계산해 SRI와 crossorigin을 적용했다.
- `css/base.css`, `css/layout.css`에서 Lenis와 충돌하는 CSS 스크롤 스냅을 제거했다. 기존 휠 가로채기/화면 강제 전환 및 Web Animation 모듈(`screen-scroll.js`, `scroll-effects.js`)을 제거하고 `scroll-motion.js`, `selected-video.js`로 교체했다. 이번 요청은 연속적인 부드러운 스크롤을 우선한다.
- Lenis는 lerp 0.085, autoRaf false, syncTouch false로 설정했다. GSAP ticker가 초 단위를 밀리초로 바꿔 Lenis를 갱신하고, Lenis scroll 이벤트에서 ScrollTrigger를 갱신한다.
- 헤더는 첫 화면에서 방향에 따라 숨고 나타나며, 두 번째 섹션 진입 구간에서는 다시 표시되어 상단에 고정된다. GSAP transform/opacity를 사용하며, 모바일 메뉴를 열 때 헤더 transform을 지워 fixed 메뉴의 기준이 뷰포트로 유지되도록 했다.
- 두 번째 섹션 타이틀을 단어 span으로 구성하고 ScrollTrigger로 단어 리빌, 타이틀 이동, 세로 카드의 패럴랙스/작은 스케일 변화를 연결했다. 미디어가 첫 화면으로 넘치지 않도록 섹션 경계를 clip했다. 첫 화면의 이미지 구성은 변경하지 않았다.
- `main.js` 메뉴에서 Lenis stop/start와 닫힘 완료 후 부드러운 앵커 이동을 연결했다. 열린 메뉴 안은 data-lenis-prevent로 일반 스크롤을 허용한다. 앵커는 URL 이력과 스킵 링크 포커스를 유지한다.
- `prefers-reduced-motion`에서는 GSAP 컨텍스트를 정리하고 일반 스크롤과 최종 콘텐츠를 표시한다. CDN 로드 실패 시에도 본문/링크/메뉴는 기본 동작한다. 영상의 수동 정지·화면 밖 정지·숨긴 탭 정지를 별도 모듈로 유지했다.
- 배경은 #000, 두 번째 섹션 회색은 #888로 적용하고 행간을 조정했다. 모션 수치/행간은 사용자 요청에 맞춘 이번 구현의 조정값이며 원본 사이트 실측값이 아니다. GSAP가 동적 인라인 transform/opacity를 쓰는 것은 요청된 라이브러리 동작에 필요한 예외로 코드에 설명했다.
- `document/002-scroll-motion.md`에 HTML/CSS/JavaScript 코드 발췌와 설정값, 공식 문서 링크를 정리했다.
- 검증: JS 문법과 Node 실행 검증에서 단일 GSAP ticker, Lenis 시간 단위, 세 가지 스크롤 모션, 헤더 방향/섹션 진입, 메뉴 잠금/해제, 앵커·포커스·이력, 반응형 정리, 모션 감소, 라이브러리 실패/지연 로딩, 단일 main/h1, 첫 화면 타일 8개와 로컬 경로를 확인했다. CDN 5개 응답과 무결성 해시를 확인했다. 실제 브라우저 모션·뷰포트 검수는 미실시다.
